## CONTEXT

Stage 2 left one known gap: the conversation thread list preview for call rows relies on
the body text written at persistence time ("📞 Missed call" etc.) rather than branching
on `messageType`. If that copy ever changes, the preview silently drifts. The fix is
proper: include `messageType` in the `latestMessage` projection from the backend, extend
the frontend Conversation type, and switch on `messageType` in the preview renderer.

**Clean Machine is live.** SMS thread previews must be byte-identical after this change.

## THE FIX — UP TO THREE CHANGES

### Change 1 — Backend: add `messageType` to latestMessage projection (if missing)

Find the query that builds the conversation list. In the `latestMessage` subquery
or JOIN, add `message_type` to the SELECT alongside `body`/`content`.

This is one line in a SQL fragment or Drizzle select object. Do not restructure the
query — surgical addition only.

If `messageType` is already returned, skip this change and note it in the report.

### Change 2 — Frontend type: add `messageType` to latestMessage shape

Find the `Conversation` interface (or wherever `latestMessage` is typed).
Add `messageType` as an optional field:

```typescript
latestMessage?: {
  body: string;        // existing
  messageType?: 'sms' | 'call_inbound' | 'call_missed' | 'voicemail'; // add
  // ... other existing fields
} | null;
```

If the type is auto-inferred from the schema, confirm `messageType` flows through
automatically from Change 1 and skip this change.

### Change 3 — Frontend: switch on `messageType` in preview renderer

In `NightOpsConversationList.tsx`, find where the preview text is rendered.
Replace the raw body/content read with a function that branches on `messageType`:

```typescript
const getPreviewText = (latestMessage?: { body?: string; messageType?: string } | null): string => {
  switch (latestMessage?.messageType) {
    case 'call_inbound': return '📞 Inbound call';
    case 'call_missed':  return '📞 Missed call';
    case 'voicemail':    return '📞 Voicemail';
    default:             return latestMessage?.body ?? '';
  }
};
```

Use the actual field names found in the verification step — `body`, `content`, or
whatever the real field is. The SMS default path (`return latestMessage?.body ?? ''`)
must produce identical output to the current code for all existing SMS threads.
