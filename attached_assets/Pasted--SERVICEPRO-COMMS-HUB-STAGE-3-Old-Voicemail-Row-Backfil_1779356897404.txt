## CONTEXT

Comms Hub Stage 1 added `message_type` to the `messages` table (default `'sms'`).
Voicemail rows created BEFORE Stage 1 were written by `voicemailConversationService`
with `messageType='sms'` and `metadata->>'type' = 'voicemail'`. They render as old
cyan SMS bubbles instead of the new CallCard component.

This stage fixes that with a single backfill migration. No code changes. The CallCard
component already handles `messageType='voicemail'` correctly — the rows just need
the right value.

**Clean Machine is live.** Verify row counts before and after. The backfill must
not touch any SMS rows or any rows without the voicemail metadata marker.

## STEP 2 — WRITE AND APPLY THE MIGRATION

**Do NOT use drizzle-kit push or drizzle-kit generate.**

Create `migrations/0009_backfill_voicemail_message_type.sql`:

```sql
-- Comms Hub Stage 3: backfill pre-Stage-1 voicemail rows to correct message_type
-- Safe: only touches rows where message_type='sms' AND metadata marks them as voicemail
-- All other rows (real SMS, call_inbound, call_missed) are unaffected

UPDATE messages
SET message_type = 'voicemail'
WHERE message_type = 'sms'
  AND metadata->>'type' = 'voicemail';
```

Apply it:
```bash
psql "$DATABASE_URL" -f migrations/0009_backfill_voicemail_message_type.sql
```
