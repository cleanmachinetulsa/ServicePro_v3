## CONTEXT

`useUiExperienceMode` (or equivalent hook) initializes UI mode state to a hardcoded default
(likely `'simple'`) before the API response returns. This causes the sidebar and any
mode-gated components to render in the wrong state for a visible flash on every page load —
items appear then disappear, or the wrong nav shows briefly.

**Clean Machine is live. The fix must not change any behavior — it only eliminates the flash.**

## THE FIX — EXACTLY TWO CHANGES TO THE HOOK

### Change 1: Initialize from localStorage

Find the `useState` call that sets the default mode. Replace the hardcoded default with a
localStorage read that falls back to the hardcoded value:

**Before (example — match actual code):**
```typescript
const [mode, setMode] = useState<UiExperienceMode>('simple');
```

**After:**
```typescript
const STORAGE_KEY = 'sp:uiExperienceMode';

const getInitialMode = (): UiExperienceMode => {
  try {
    const stored = localStorage.getItem(STORAGE_KEY);
    if (stored === 'simple' || stored === 'advanced' || stored === 'nightops') {
      return stored;
    }
  } catch {
    // localStorage unavailable (SSR / private browsing edge case)
  }
  return 'simple'; // match whatever the original hardcoded default was
};

const [mode, setMode] = useState<UiExperienceMode>(getInitialMode);
```

> IMPORTANT: The `getInitialMode` function must use the actual valid mode values from
> the codebase — not the examples above. Read them from the type/enum before writing.

> IMPORTANT: Pass `getInitialMode` (no parentheses) to `useState` so it only runs once
> on mount, not on every render.

### Change 2: Persist to localStorage after API returns

Find the place where `setMode(...)` is called after the API response resolves.
Add a localStorage write immediately before or after:

**Before (example — match actual code):**
```typescript
setMode(data.uiMode);
```

**After:**
```typescript
try {
  localStorage.setItem(STORAGE_KEY, data.uiMode);
} catch {
  // ignore write failures
}
setMode(data.uiMode);
```

> The `STORAGE_KEY` const must be defined once at the top of the hook (or module scope),
> not redeclared. Make sure Change 1 and Change 2 reference the same const.

## EDGE CASES (handled by the implementation above)

| Scenario | Behavior |
|---|---|
| First-ever load (nothing in localStorage) | Falls through to original default — identical to today |
| localStorage unavailable (private browsing) | try/catch swallows the error, falls back to default |
| Stored value is stale/invalid string | Validation check (`stored === 'simple' || ...`) rejects it, falls back |
| API returns a different mode than localStorage | setMode() + localStorage.setItem() update both in sync |
| User clears localStorage | Treated as first-ever load |
